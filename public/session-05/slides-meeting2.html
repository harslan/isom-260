Thing 2 · ask before acting

The 🚦 moves into the chat.

A new tool: send_email simulated — but the agent doesn't know that. That's the point
The model reaches for it → the loop pauses "🚦 I'd like to run send_email(to=cfo@…). Reply YES to approve." The call waits in PENDING
YES → the tool runs and the loop resumes. Anything else → BLOCKED and the model must say "not sent" — and never retry on its own

Thing 3 · memory that survives

Memory is a liability
A file of what your friends told your bot. Who can read it? How long do you keep it? Every chatbot vendor has this file.
/forget
The right to be forgotten
One command erases a chat in memory and on disk. GDPR Article 17, in one line of Python.

Persistence is not a feature you add. It's a responsibility you take on.

Bonus · a real-world API

Real APIs don't fail. They guess.

get_weather("Boston") → 59°F, Boston, Massachusetts a free public weather API, no key, two calls: find the place, then the forecast
get_weather("Bostn") → 48°F… Båstnäs, Sweden no error. A confident answer about the wrong continent
The fix is in the tool, not the model return matched_place, and tell the model in the system prompt: if it's not the city asked for, say so first

Your agent's reputation is decided in the 1% of calls where the API was wrong, not down.

AI for BUSINESS · the four questions

Ask these of any AI product.

"Who can use it?" and who maintains the list — the door is only as good as its gatekeeper
"What can it do without asking?" and who gets the 🚦 at 2 AM
"What does it remember, and can it forget?" persistence comes with a privacy bill. Ask to see the file
"What happens when the API is wrong?" not down — wrong. Båstnäs, Sweden

A vendor who can't answer all four with a table hasn't built an agent. They've built a demo.
