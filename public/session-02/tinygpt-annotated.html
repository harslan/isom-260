1 · Data — Turning Names Into Numbers

Before anything can learn, text has to become numbers. This section downloads a list of thousands of baby names and converts every character into an integer. That's the entire data pipeline.

notebook · cell: data
1names = urllib.request.urlopen(url).read().decode().splitlines()
2text = "\n".join(names)
3chars = sorted(set(text))                # the 27-symbol vocabulary
4stoi = {c: i for i, c in enumerate(chars)}
5itos = {i: c for c, i in stoi.items()}
6data = torch.tensor([stoi[c] for c in text])
Line 1
Download the dataset

One line fetches a text file from the internet (urlopen), reads it, converts raw bytes into readable text (decode), and splits it into a list — one baby name per entry. That's the entire "data acquisition" phase of this AI project.

Line 2
Glue it back into one long string

All the names are joined into a single stream of text, separated by the newline character ("\n"). That newline matters: it's how the model will eventually learn that names end. When it generates a newline, a name is finished.

Line 3
The vocabulary: 27 symbols

set(text) keeps exactly one copy of each distinct character; sorted puts them in a fixed order. Result: the 26 lowercase letters plus the newline — 27 symbols. This is everything the model can ever read or write. Nothing outside this list exists for it.

Lines 4–5
stoi / itos: the two-way phrasebook

Neural networks only eat numbers — they cannot see letters. stoi ("string to integer") assigns each character a number: a→1, b→2, …. itos is the same dictionary flipped, for translating the model's numeric answers back into letters. Every conversation with every AI passes through a phrasebook like this — in, and back out.

Line 6
The entire corpus as one number stream

Every character in the whole text is replaced by its number and packed into a tensor — one giant list of integers. This single object is the training data. The model will never see anything else: no meanings, no sounds, no culture. Just this stream of numbers, and the patterns hiding in it.

Frontier note · Session 3
In GPT-6-class models, this step is called tokenization

Frontier models do exactly this, but instead of 27 letters they use ~100,000 sub-word tokens — chunks like "straw", "berry", "ing". Same idea, bigger phrasebook. Karpathy's rule of thumb: "every weird LLM behavior traces back to tokenization." We'll see why in Session 3.

2 · Batches — The Text Labels Itself

Training needs examples: "here's an input, here's the right answer." This function manufactures them — and notice that no human wrote any answers.

notebook · cell: batches
1def get_batch(batch_size=64):
2    ix = torch.randint(len(data) - block_size - 1, (batch_size,))
3    x = torch.stack([data[i:i+block_size] for i in ix])
4    y = torch.stack([data[i+1:i+block_size+1] for i in ix])
5    return x.to(device), y.to(device)
Line 1
A function that grabs a random handful

Each time it's called, this function serves up 64 practice examples. Training will call it 2,501 times — a fresh random handful every loop, so the model never just memorizes one page.

Line 2
Pick 64 random starting points

randint throws 64 darts at the number stream — 64 random positions to start reading from. The - block_size - 1 just makes sure no window runs off the end of the data.

Line 3
x: 64 windows of 16 letters

From each dart position, cut out a window of 16 consecutive characters (block_size) and stack them into a neat 64×16 grid. These are the model's inputs — 64 little snippets of names.

Line 4 · The big idea
y is x shifted by exactly ONE character

Look closely: y is the same windows, starting one position later. So for every letter in x, the "correct answer" in y is simply the next letter in the text. That is the entire supervision of a language model. No labels, no teachers, no human graders — the text labels itself. This is why the whole internet is trainable: every sentence ever written comes pre-packaged with its own answer key, one character to the right.

Line 5
Ship both to the GPU

.to(device) moves the grids onto the graphics chip, which does thousands of multiplications in parallel. Plumbing, not intelligence.

3 · The Block — Attention + Thinking

This is the famous Transformer block — the component the "Attention Is All You Need" paper introduced in 2017 and that every frontier model still stacks by the hundred. One block = one reading pass: look around (attention), then think it over (MLP).

notebook · cell: transformer block
1class Block(nn.Module):
2    def __init__(self):
3        super().__init__()
4        self.ln1 = nn.LayerNorm(n_embd)
5        self.attn = nn.MultiheadAttention(n_embd, n_head, batch_first=True)
6        self.ln2 = nn.LayerNorm(n_embd)
7        self.mlp = nn.Sequential(nn.Linear(n_embd, 4*n_embd), nn.GELU(),
8                                 nn.Linear(4*n_embd, n_embd))
9    def forward(self, x):
10        T = x.shape[1]
11        mask = torch.triu(torch.ones(T, T, device=x.device), 1).bool()
12        h = self.ln1(x)
13        x = x + self.attn(h, h, h, attn_mask=mask, need_weights=False)[0]
14        return x + self.mlp(self.ln2(x))
Lines 1–3
Declare a reusable part

A class is a blueprint. This one defines a single Transformer block; later, TinyGPT will stack two of them. GPT-6-class models stack 100+ copies of essentially this same blueprint.

Lines 4 & 6
LayerNorm: keep the numbers in a healthy range

As numbers flow through many layers of multiplication, they can drift huge or shrink to nothing. LayerNorm re-centers them before each step — like normalizing exam scores from different classes before averaging them, so no single wild scale dominates. Unglamorous, essential: without it, deep networks simply refuse to train.

Line 5
MultiheadAttention: four parallel lenses

Attention is the mechanism that lets each letter look back at earlier letters and decide which ones matter for predicting what comes next. "Multihead" with n_head=4 means four of these lenses run in parallel, and each learns to look for something different — one might track vowels, another the previous consonant, another distance from the start of the name. Nobody assigns those jobs; they emerge from training.

Lines 7–8
MLP: the per-position thinking layer

After looking around, each position thinks privately. The Linear → GELU → Linear sandwich expands each 64-number summary to 256 numbers (4× scratch space to work in), passes it through a soft on/off gate (GELU — the modern cousin of the neuron switch you saw in the playground), then compresses back to 64. Expand, compute, condense.

Lines 10–11 · The single most important line
The causal mask: a triangle of "no peeking"

torch.triu builds a triangle of flags covering every future position, and the mask forbids attention from looking there. During training the model sees a whole 16-letter window at once — this triangle forces each position to predict the next letter using only the past. Delete this one line and the model could "predict" letters it can already see: perfect score, zero learning. This is the line that makes it a language model rather than a cheater.

Lines 12–13
self.attn(h, h, h): the text attends to ITSELF

Attention takes three inputs — roughly what am I looking for, what's on offer, what do I take. Passing the same sequence h for all three means the sequence queries itself: that's the "self" in self-attention. Every letter asks every earlier letter, "are you relevant to me?" and blends what it hears.

Lines 13–14 · The x+ pattern
Residual connections: keep what you had, ADD the refinement

Notice both lines say x + … rather than replacing x. Each layer contributes an edit on top of the running total instead of overwriting it — like a memo passing through reviewers who each add margin notes rather than rewriting the whole thing. This small trick is what makes very deep networks trainable at all; without it, information degrades layer by layer and learning stalls.

4 · TinyGPT — Assembling the Whole Model

Ten lines. This is the entire architecture of the model you trained — and, at a conceptual level, the entire architecture of the frontier models you'll use all semester.

notebook · cell: the model
1class TinyGPT(nn.Module):
2    def __init__(self):
3        super().__init__()
4        self.tok = nn.Embedding(len(chars), n_embd)
5        self.pos = nn.Embedding(block_size, n_embd)
6        self.blocks = nn.Sequential(*[Block() for _ in range(n_layer)])
7        self.head = nn.Linear(n_embd, len(chars))
8    def forward(self, idx):
9        T = idx.shape[1]
10        x = self.tok(idx) + self.pos(torch.arange(T, device=idx.device))
11        return self.head(self.blocks(x))
Line 4
tok: the map of meaning

This is the embedding table you visualized in class — each of the 27 characters gets its own learned list of 64 numbers. Before training those numbers are random noise; after training, similar-behaving letters drift near each other on the map. Meaning, as geometry.

Line 5
pos: "where am I in the sequence?"

Here's a secret: attention by itself is order-blind — it sees the letters of a window as a bag, not a sequence. "dog" and "god" would look identical. The fix: give each of the 16 positions its own learned 64-number vector, so position 1 feels different from position 9.

Line 10
tok + pos = "what" + "where"

Each letter's meaning vector is added to its position vector. Every slot entering the blocks now carries both which character I am and where I sit. Simple addition — and it works.

Lines 6 & 11
Two stacked Blocks: read the text twice, deeper each time

The input flows through Block 1, and its refined output flows through Block 2. Pass one catches surface patterns (letter pairs); pass two builds on them (syllable shapes, name endings). Depth = re-reading with better notes each time.

Line 7 & 11
head: from a 64-number summary to 27 scores

The final layer converts each position's 64-number summary into 27 raw scores called logits — one per possible next character. Higher score = the model finds that letter more plausible next. Turn those into percentages and sample one, and you get the invented names you watched scroll by.

Frontier note
What GPT-6 changes — and what it doesn't

GPT-6-class models differ by: a ~100,000-token vocabulary instead of 27 letters, 100+ blocks instead of 2, and thousands of embedding dimensions instead of 64 — and conceptually nothing else. Embed, add position, stack blocks, score the vocabulary. You have now read the architecture of the frontier.

5 · The Training Loop — Where Learning Happens

Six lines. This is the loop you sat and watched — the loss falling from 3.5 toward 1.75 while the invented names went from gibberish to plausible.

notebook · cell: training
1opt = torch.optim.AdamW(model.parameters(), lr=3e-3)
2model.train()
3for step in range(2501):
4    x, y = get_batch()
5    loss = F.cross_entropy(model(x).view(-1, len(chars)), y.view(-1))
6    opt.zero_grad(); loss.backward(); opt.step()
Line 1
AdamW: a smarter step-size manager

The optimizer is the thing that will actually adjust the weights. AdamW is plain gradient descent plus bookkeeping: it remembers each weight's recent history and gives steady ones bigger steps, jittery ones smaller steps. lr=3e-3 is the base step size — the same "learning rate" knob you saw in the neuron playground.

Lines 2–4
2,501 loops of: grab examples, try, get graded

model.train() flips the model into learning mode; then the loop runs 2,501 times. Each pass: grab a fresh random batch of 64 windows, predict, get scored, adjust. That repetition is the whole of "learning." There is no other mechanism.

Line 5 · The number you watched
cross_entropy: the surprise meter

For every position, take the probability the model assigned to the true next letter and compute −log(that probability) — big when the model is surprised, near zero when it saw it coming — then average over the whole batch. This is THE number you watched fall from 3.5 to about 1.75, and it's exactly the average of the surprise gauge from the Beat-Your-AI game. All of training is one instruction: be less surprised by the data.

Line 6 · opt.zero_grad()
Wipe the slate

Clear last loop's adjustment notes so this batch's feedback starts fresh. Housekeeping.

Line 6 · loss.backward()
Backpropagation — the most important call in modern AI

This computes, for all 104,475 weights simultaneously, which direction each should move to make the surprise slightly smaller — which way is "downhill." It works by walking the chain of arithmetic backwards from the loss to every weight that contributed. One line of code; the discovery underneath it is why the deep-learning era exists.

Line 6 · opt.step()
Gradient descent: take the tiny step

Nudge every weight a small amount in its downhill direction. This is the Loan Officer's sliders — except instead of you dragging three sliders by hand, 104,475 sliders move themselves, a hair at a time, 2,501 times. Zoom out and that's all "training an AI" ever means, from TinyGPT to the frontier: measure surprise, find downhill, step. Repeat until the money runs out.
